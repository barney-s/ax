## Deviations from the Runbook
1. **Substrate WorkerPool Deployment**:
   - **Reason**: The Substrate core install (`hack/install-ate.sh --deploy-ate-system`) installs control plane components (`atelet`, `ate-controller`, `ate-api-server`, `atenet`) but does not instantiate a `WorkerPool` CRD instance. Spawning any Actor resulted in `ResourceExhausted: no free workers available`. Deploying the Substrate worker pool (`ate-setup deploy demo sandbox`) created the necessary gVisor worker pods to schedule AX actors.
2. **Cloud Build Ignore Exclusions**:
   - **Reason**: The repository `.gitignore` and `.dockerignore` files ignore `bin/`. Compiling `bin/linux_amd64/ax-task-runner` locally and running `gcloud builds submit` caused `gcloud` and `docker` to ignore the precompiled binary during image build. Supplying temporary `.gcloudignore` and `.dockerignore` overrides during Cloud Build packaging unblocked building `ax-task-runner`.

## Recommended Runbook Changes
1. **Add WorkerPool Provisioning Step**:
   In `docs-exploration/runbooks/deploy-gcp.md`, under Step 5 (Install Substrate Control Plane), add:
   ```bash
   # Deploy Substrate WorkerPool to provide execution capacity for actor sandboxes
   go run ./cmd/ate-setup deploy demo sandbox || true
   ```
2. **Document Task-Runner Build Packaging**:
   In Step 8 (Build and push ax-task-runner), include the `.gcloudignore` / `.dockerignore` handling so `bin/linux_amd64/ax-task-runner` is preserved in the Cloud Build context.
3. **Digest-Pinned Actor Templates**:
   Note in the runbook that Substrate requires `spec.image` in Actor specs to be pinned by digest (`@sha256:...`) to enable deterministic snapshotting.
