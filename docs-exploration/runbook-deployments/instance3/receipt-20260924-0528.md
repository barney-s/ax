## Attempt Log

### Attempt 1: GKE Cluster Timeout & GCS Bucket Labeling Flags
- **What Failed:** `gcloud container clusters create` blocked for >5 minutes without stdout output, causing a command execution timeout. Additionally, `gcloud storage buckets create` failed with `unrecognized arguments: --labels=...`.
- **Evidence:** `Command was automatically cancelled because it exceeded the timeout of 5.0 minutes without output`, `ERROR: (gcloud.storage.buckets.create) unrecognized arguments: --labels=repo-agent-instance=ax-instance3`.
- **What was changed:** Added `--async` to `gcloud container clusters create` followed by a status polling loop with periodic timestamp outputs to prevent quiet timeouts. Updated GCS bucket labeling to use `gcloud storage buckets update --update-labels=...`.

### Attempt 2: Substrate Source Build ClusterTrustBundle Incompatibility
- **What Failed:** Building Agent Substrate from `main` branch source failed during `./hack/install-ate.sh` because Substrate `main` expects the Kubernetes `ClusterTrustBundle` API which is an alpha feature unavailable on standard GKE clusters.
- **Evidence:** `Waiting for podcertificate ClusterTrustBundles to be ready... Error: waiting for ClusterTrustBundle podidentity.podcert.ate.dev:identity:primary-bundle: context deadline exceeded`.
- **What was changed:** Transitioned Substrate installation to the stable published Helm chart `v0.0.12` (`oci://ghcr.io/kagent-dev/substrate/helm/substrate`), aligning with GKE standard capabilities.

### Attempt 3: Helm CRD Schema & RBAC Reflector Blockers
- **What Failed:** Substrate Helm chart installation failed due to `sandboxconfigs.ate.dev` CRD enforcing a required `pauseImage` property that the v0.0.12 Helm template omitted. Additionally, `ate-api-server` pods repeatedly crashed with RBAC permission errors listing `storageclasses` and `csidriverconfigs`.
- **Evidence:** `SandboxConfig.ate.dev "gvisor-default" is invalid: [spec.pauseImage: Required value]`, `User "system:serviceaccount:ate-system:ate-api-server" cannot list resource "storageclasses" in API group "storage.k8s.io" at the cluster scope`.
- **What was changed:**
  1. Added an automated CRD schema patch via `jq` to make `pauseImage` optional on `sandboxconfigs.ate.dev`.
  2. Applied custom ClusterRole and ClusterRoleBinding (`ate-api-server-extra-role` and `ate-api-server-extra-binding`) granting `storageclasses` and `csidriverconfigs` permissions before platform initialization.

### Attempt 4: Container Build & Substrate 0.0.12 Protobuf Compatibility
- **What Failed:** No local Docker daemon was available to execute `make push-task-runner`. Furthermore, submitting tasks to Substrate 0.0.12 produced protobuf schema validation errors because the newer client proto used `ObjectRef` (field 4) instead of fields 2 (`actor_template_namespace`) and 3 (`actor_template_name`).
- **Evidence:** `docker: command not found`, `rpc error: code = InvalidArgument desc = [actor.actor_template_namespace: Required value, actor.actor_template_name: Required value]`.
- **What was changed:**
  1. Configured Go cross-compilation for `ax-task-runner` (`GOOS=linux GOARCH=amd64`) and submitted image builds directly to Google Cloud Build.
  2. Implemented binary protobuf raw wire injection in `internal/substrate/client.go` using `google.golang.org/protobuf/encoding/protowire` to populate fields 2 and 3 dynamically for backward compatibility.
  3. Created `ActorTemplate` resources with pinned container image digests (`@sha256:9e0e257196695336ad585cee6a40bcea0c0b069c68a86015d8d0d71c0d0b3d41`).
