# AX Activity: September 7, 2026 – September 21, 2026

## Themes: The Great AX Restructuring (v0.3.0)

Over the past two weeks, AX underwent a monumental architectural evolution, culminating in the release of **v0.3.0** on September 20, 2026. The platform has officially transitioned from a monolithic CLI utilizing an embedded Python harness to a highly scalable, distributed, microservice-oriented orchestration layer for sandboxed AI agent tasks.

To achieve high-throughput execution of millions of ephemeral agent tasks without overloading traditional control planes (like Kubernetes' etcd), AX moved its entire state store into **Redis** and adopted **Redis Streams** as its decoupled, asynchronous work queue. The previous database backends (PostgreSQL, SQLite), the SQL event log, and the legacy Python harness have been fully deprecated and excised. 

Alongside this shift, core maintainers conducted a massive housekeeping sweep on September 20, 2026, closing nearly a dozen legacy issues and pull requests (e.g., #337, #318, #315, #314, #313, #307, #299, #298, #286, #268) related to the deprecated embedded harness, SQLite/PostgreSQL configuration, and legacy dashboard. This effectively reset the repository's backlog to focus entirely on the new Redis-backed architecture.

Following the v0.3.0 release, activity has pivoted to post-migration stabilization, with a surge of detailed bug reports and architectural gaps surfaced by the community and core maintainers.

## Notable Merges

- **Restructure AX into general-purpose orchestration layer (`dc4f36c`, PR #343)**: The massive core commit that split AX into three dedicated binaries (`ax-server`, `ax-controller`, and `ax-task-runner`), implemented the Redis store/stream engine, and updated the documentation footprint.
- **Workflow & Workflow Permissions Hardening (`d8ed0fe`)**: Pinned GitHub Actions versions and added strict read-only repository permissions for CI pipelines, establishing production security standards for v0.3.0.

## Code Base Churn & Hotspots

With the complete rewrite, churn is concentrated across three primary subsystems:
1. **`internal/store/` & `internal/controller/`**: Migrated from CRD/SQL drivers to a custom Go client interface mapping tasks to Redis Hashes (`internal/store/redis`) and processing reconciliation events from Redis Streams (`internal/controller/worker.go` and `reconciler.go`).
2. **`pkg/apis/v1alpha1/`**: New central protobuf definitions (`ax.proto`) establishing gRPC schemas for `Task`, `Workspace`, `Gateway`, and `Model` resources.
3. **`runner/` & `internal/workspace/`**: The new `ax-task-runner` sandbox supervisor that performs git workspace cloning, skill bootstrapping, and container-level process supervision.

## Maintainer Asks & Contribution Opportunities

The community and maintainers have identified several critical bugs, reliability gaps, and architectural extensions following the v0.3.0 release. Key contribution items include:

### 1. Critical Concurrency & Synchronization Bugs
- **State Concurrency Overwrite (Issue #352)**: `UpdateTaskStatus` reads the task from Redis and later overwrites the whole record without checking its version. A concurrent task spec edit (e.g. image update or suspension) is silently lost.
  - *Status:* Regression test `TestReviewStatusUpdatePreservesConcurrentSpecEdit` is available on branch `test/review-regressions`.
- **Spec/Actor Template Sync Gap (Issue #353)**: Updating a task's container image provisions a new `ActorTemplate`, but because the actor already exists, the controller leaves the actor bound to its old template, causing spec updates to be ignored.
  - *Status:* Regression test `TestReviewTaskEditUpdatesActorTemplate` is available on branch `test/review-regressions`.
- **First Subscription Event Backlog Skip (Issue #354)**: On initial startup, the controller worker group creates a Redis consumer group at `$` (current stream tail), completely skipping tasks published prior to startup.
  - *Status:* Regression test `TestReviewSubscriptionDeliversPreexistingTasks` is available on branch `test/review-regressions`.
- **Controller Nil-Pointer Panic (Issue #349)**: Applying a task without an explicit `spec` causes the controller to crash with a nil-pointer panic. Requires default initialization or strict validation rules in `ValidateTask`.

### 2. Sandbox, Security & Reliability
- **Gateway Missing Validation / Wildcard Egress (Issue #350)**: A task referencing a nonexistent Gateway is accepted because the lookup failure leaves the resolved gateway as `nil`. The reconciler treats `nil` as unrestricted, granting wildcard egress instead of failing.
  - *Status:* Regression test `TestReviewMissingGatewayDoesNotGrantWildcardEgress` is available.
- **Task Secrets Exposure (Issue #348)**: `EnvVar` has no `valueFrom` reference, forcing credentials to be supplied in plaintext. A unified secret reference model is needed.
- **Redis Queue Reliability (Issue #351)**: No `XPENDING`/`XCLAIM` event recovery mechanism exists to claim or retry unacknowledged tasks if a controller worker crashes.
- **Completed Task Phase Tracking (Issue #346)**: Tasks report `phase: Running` indefinitely after their process exits. Needs exit code monitoring and transition to terminal phases (`Succeeded`/`Failed`).
- **Workspace Silent Git Clone Failures (Issue #347)**: Git clone failures do not block the transition to `WorkspaceReady: True`, causing tasks to run in empty workspaces.
- **Gateway TLS Blockage (Issue #345)**: Hostname entries in the egress gateway allowlist block all TLS egress due to SNI-based filtering issues.

### 3. Design Discussions & Future Improvements
- **Task Tree Authorization & Signed Attenuable Grants (Issue #357)**: Discussion on task-scoped authority for nested task trees, utilizing signed, attenuable grants to prevent sub-tasks from inheriting parent write authority.
- **Nomenclature: Rename Model to ModelInstanceConfiguration (Issue #356)**: Renaming `Model` to avoid confusion since it represents named provider configurations/parameters, not a machine learning model.
- **Better Developer Examples (Issue #355)**: Updating examples to represent modern agentic workloads (e.g., log anomaly detection, decision log consolidation) rather than deterministic Go builds.
- **Porting Antigravity SDK to Go (Issue #341)** & **Configurable Sandbox Runtimes (Issue #344)**: Expanding sandboxed execution and runtimes (e.g. gVisor, Firecracker).
- **Observability and OpenTelemetry Exposition (Issue #13)**: Integrating OTLP metrics, logs, and trace context propagation across the client-server boundary and outbound tool calls.

## What a Returning Contributor Must Know

- **No more SQL/CRD state**: If you have local sqlite databases or custom Kubernetes operator configs, delete them. Everything now requires a running **Redis** server.
- **Three-Binary Architecture**: Debugging now requires running `ax-server` (for APIs), `ax-controller` (for state reconciliation), and `ax-task-runner` (the container supervisor).
- **Run the new test suite**: Execute `go test ./internal/store/...` and `go test ./internal/controller/...` to verify local Redis integration.
- **Check Review-Regressions Branch**: Core maintainers have provided reproducible regression test suites on the `test/review-regressions` branch for key bugs (#352, #353, #354). Check them out to understand structural expectations.
- **Environment & Build Verification**: All workspace tests compile and pass successfully (verified on Sep 21, 2026), confirming compilation and basic unit-test health for the redesigned distributed architecture.
